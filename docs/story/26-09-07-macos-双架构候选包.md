# 26-09-07 macOS 双架构（arm64 + x64）候选包

## 背景

`repos/mac/release/` 此前只有 `LayoutSee-0.1.0-arm64.dmg`，且 `package.mjs` 硬性拒绝在非 arm64 构建机运行。实测反馈：Mac 2020（Intel/M1 存疑）安装报错，本机 Mac 2023 M3（arm64）正常。Story-0827 规格早有约定「V0.1 分别产出 arm64 和 x64 两套制品，不承诺 universal」。

## 根因分析（2020 机器安装错误）

检查旧 DMG 产物元数据：

- `LSMinimumSystemVersion` = **13.0**（Ventura），由 Electron 44 框架 minos=13.0 决定（`otool` 实测）。
- 旧包仅 arm64：Intel 机器直接无法安装；Apple Silicon 若系统 < macOS 13 也会被拒（弹「需要较新 macOS」）。
- 未签名未公证（ad-hoc），跨渠道传输会触发 Gatekeeper「已损坏」误报，需 `xattr -cr`（与架构无关的常见坑）。

结论：需要 x64 包解决 Intel；arm64 包要求系统 ≥ macOS 13 属 Electron 44 硬门槛，无法降级。

## 改动

1. `repos/mac/scripts/package.mjs` 重写为按 `--arch arm64|x64|all`（缺省 = 构建机架构）逐架构执行：PyInstaller Core → 资源暂存 + manifest → electron-builder DMG。
   - core 依赖改为从 `repos/core/pyproject.toml` 解析（单一事实源，不再双写）。
   - x64 构建在 arm64 主机上经 Rosetta 运行 x86_64 CPython（python-build-standalone 3.12.14，缓存 `repos/mac/build/python-x64/`，首次自动下载，`PBS_MIRROR` 可换源）。
   - manifest 的 `pythonVersion` 改为实测值、`targetArch` 随架构。
2. `repos/mac/electron-builder.yml`：`mac.target` 不再固定 arch（由 CLI 下发），显式 `minimumSystemVersion: "13.0"`。
3. `package.json`（mac + 根）新增 `package:mac:x64` / `package:mac:all`。
4. 产物归档：每个架构构建完把 DMG 与解包 .app 收敛到 `release/mac-arm64/`、`release/mac-x64/` 目录，避免从 release 根误拿错架构安装包。

## 验证

- x64 全流程构建通过；DMG 内 app/Electron Framework/core 均为 x86_64，manifest `targetArch: x64`、python 3.12.14。
- x64 Core 在 M3（Rosetta）实跑：READY 输出、`/api/v1/info` 会话校验通过、首页 200。
- arm64 路径回归打包通过。

产物：`repos/mac/release/mac-arm64/LayoutSee-0.1.0-arm64.dmg`（约 143MB）与 `repos/mac/release/mac-x64/LayoutSee-0.1.0-x64.dmg`（约 148MB），归档在各自架构目录（同目录含解包 .app），均未签名未公证。

## 遗留

- Apple 签名 / 公证 / staple 与干净机门禁未做（需开发者证书）。
- 需 Intel 真机与 2020 机器实测安装。
