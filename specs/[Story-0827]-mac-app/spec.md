本规格综合 PRD v0.9、可运行 UI 原型、设计系统、交互原型和 macOS 桌面壳技术评审形成。产品范围以 PRD 为准，当前构图、密度和主要交互手感以可运行原型为准，语义 Token、可访问性和禁止项以设计系统为准，工程边界、安全基线、性能门槛与冲突裁决以技术评审为准。

## 问题陈述

移动应用开发者、QA 和 AI Agent 缺少一个共同、可信的运行时 UI 事实源。开发者可以看到真机画面，但难以同时获得与画面严格同步的层级树、节点属性、稳定选择器和可量化的布局问题；AI Agent 通常只能消费截图或原始 XML，信息噪声高、Token 成本高，也无法安全地把“看到元素”与“操作元素”连接起来。

现有可运行原型已经验证了 LayoutSee 的主要页面构图、工作台信息密度、双层可拖拽布局和基础交互，但它仍是基于静态数据与模拟延迟的浏览器演示。正式 Web 工程与 macOS 壳只有骨架，缺少真实 URL 路由、版本化契约、设备与媒体连接、进程守护、安全桥、错误恢复、测试基础设施和双架构发行能力，不能直接作为可发布桌面应用。

V0.1 需要交付一个可离线运行的 macOS 桌面应用：安全地拉起并守护本地 Core，在真实 Android 设备上完成接入、投屏、操控、布局抓取、元素定位、语义摘要、异常诊断、MCP 接入和受限插件加载，并在服务、设备或媒体链路失败时保留仍可使用的内容和清晰的恢复路径。

## 解决方案

交付采用“Electron macOS 壳 + 单一 React Web UI + Python Core sidecar”的三层本地架构：

- Electron 壳负责原生窗口、单实例、启动与错误页、系统能力白名单、Core 生命周期、日志入口、主题同步和发行，不承载设备业务逻辑。
- 单一 Web UI 负责设备管理、群控预览、设备工作台、五个任务 Tab、接入诊断与设置，通过版本化 HTTP、WebSocket 和 MCP 契约消费 Core 能力。
- Core 负责 Android 设备接入、布局快照、媒体与控制、语义摘要、异常诊断、MCP、插件宿主数据和 Web 静态资源托管。Core 内部算法与驱动设计由独立技术方案负责，本规格冻结其对外契约、集成行为和发布门禁。
- `LayoutSnapshot` 是画面、层级树、节点属性、语义摘要、异常诊断和 Agent 引用的唯一布局事实源，避免各消费方使用互不一致的数据。
- 日常自动化使用“真实 Electron 应用 + 可控假 Core 子进程 + 正式 Web 构建产物”这一主要测试接缝；真实 Android 与双架构签名公证包作为发布门禁。

V0.1 成功意味着：用户可以在无需登录、License 或联网校验的情况下安装并启动应用，连接 Android 真机，稳定完成“设备发现 → 投屏 → 原子抓取 → 元素定位 → 摘要或诊断 → MCP 操作”的完整链路；应用同时满足安全、可恢复、可访问、性能和进程回收要求。

## 用户故事

### 应用启动与生命周期

1. 作为移动端开发者，我希望双击应用后立即看到原生窗口和启动状态，从而知道应用正在工作而不是无响应。

3. 作为移动端开发者，我希望 Core 启动超过 15 秒时进入明确的错误页，从而可以重试、复制诊断信息或打开日志目录。
4. 作为移动端开发者，我希望缺少 Core 制品时仍能使用壳内置错误页，从而不依赖已经失败的服务来展示修复入口。
5. 作为移动端开发者，我希望第二次启动应用时唤醒现有窗口而不是创建重复实例，从而避免多个 Core 争用设备和端口。
6. 作为移动端开发者，我希望端口被占用时应用自动选择可用端口并更新所有配置，从而无需手动排查端口冲突。
7. 作为移动端开发者，我希望应用只连接本次启动的 Core 进程，从而不会误连本机其他同端口服务。
8. 作为移动端开发者，我希望 Core 异常退出后应用按预算自动恢复，从而减少临时故障造成的工作中断。
9. 作为移动端开发者，我希望恢复期间仍能查看最后一帧和已有快照，从而保留问题上下文。
10. 作为移动端开发者，我希望退出应用后 Core、投屏进程及其子孙进程全部结束，从而不残留进程或占用端口。

## 实现决策

### 1. 范围与事实源

- V0.1 的产品范围是 macOS 桌面应用与 Android 完整主链路；iOS、HarmonyOS、Windows、独立浏览器发布和团队 Server 不进入本 Story。
- 产品范围和量化业务验收以 PRD 为准；构图、信息密度和主要操作手感以可运行原型为迁移基线；语义 Token、可访问性和视觉禁止项以设计系统为准；工程、安全、发行与冲突裁决以技术评审为准。
- Core 内部的设备驱动、快照算法、语义摘要算法、诊断算法和 MCP 工具实现需要独立技术方案。本 Story 冻结它们的公开契约、集成行为和发布验收，不把未评审的内部实现伪装成既定决策。
- 独立日志浏览页不属于 V0.1。V0.1 必须提供壳内错误页、日志落盘、复制脱敏诊断信息和在 Finder 打开固定日志目录。
- 主页、应用、命令、MCP Inspector、存档、diff、`.lsnap`、录屏、裁切、安装应用、自动更新等未实现入口在生产包中隐藏，不保留无响应或大面积禁用入口。

### 2. 总体架构

- 应用采用 Electron 壳、单一 React Web UI 和 Python Core sidecar 三层架构。
- Electron 主进程只负责窗口、单实例、菜单、系统能力白名单、主题、Core 生命周期、日志入口和发行，不直接访问 ADB、uiautomator2 或 scrcpy 业务能力。
- Core 就绪后直接托管正式 Web 静态产物；Electron 窗口导航到该次握手得到的精确本地 origin。正式 UI 本身就是 renderer，不再增加额外 WebView 加载层。
- 业务能力统一通过版本化 HTTP、WebSocket 和 MCP 契约访问；文件选择、固定目录打开、系统主题等桌面能力只通过 preload 白名单访问。
- 控制面与媒体面分离：HTTP 承载设备、快照、应用、设置和命令，WebSocket 承载实时画面、触控与控制流。
- `LayoutSnapshot` 是全系统唯一布局事实源。画面叠加、层级树、属性、XPath、摘要、诊断和 Agent `ref` 必须引用同一快照版本。

### 3. 壳启动与 Core 生命周期

- 启动顺序固定为：创建窗口、加载壳内启动页、创建 Core 独立进程组、读取 READY、调用信息接口二次校验身份与版本、导航到精确本地 origin。
- 应用使用单实例锁；第二实例只激活现有窗口。
- 端口唯一所有者是 Core。Core 从 33299 开始原子绑定，冲突时最多递增 10 次；禁止壳先探测端口再启动 Core。
- READY 至少携带端口、进程标识、随机 nonce、产品版本、API 版本和快照 schema 版本。壳必须使用信息接口验证相同 nonce 后才信任该服务。
- Core 就绪指标为 P90 不超过 10 秒，15 秒为硬超时。超时、制品缺失、身份不匹配或版本不兼容均进入壳内错误页。
- 健康检查周期为 2 秒；连续两次失败进入异常状态。重启退避为 1、2、4 秒，最多三次，稳定运行 60 秒后重置预算。
- 恢复期间清理旧 WebSocket，最后一帧和已有快照保持只读；恢复成功后回到设备列表并提示服务已恢复。
- 退出时先停止新请求和 WebSocket，再向 Core 进程组发送 SIGTERM；3 秒后仍未退出才强杀，必须同时回收投屏等子孙进程。
- 壳与 Core 日志分文件保存，按天切分并保留 7 天。

### 4. Electron 安全基线

- 必须关闭 Node 集成，启用上下文隔离、sandbox 和 Web 安全，并关闭 `webviewTag`。
- 仅允许导航到本次握手验证的精确本地 origin；其他导航、创建窗口和权限请求默认拒绝。
- preload 不暴露 `ipcRenderer`、文件系统、任意 channel、任意路径或任意 URL。
- preload 白名单只包含应用信息、Core 会话状态、Core 状态订阅、固定日志目录、固定插件目录、ADB 路径选择、受信外部帮助入口和系统主题订阅等明确能力。
- 所有 IPC 请求必须校验来源 frame、参数 schema、路径边界和枚举值；订阅 API 必须返回取消订阅函数。
- Core 静态服务必须设置严格 CSP，拒绝内联脚本、任意远程脚本、非白名单连接和非受信插件来源。
- 生产包只允许监听 `127.0.0.1`。远程监听、远程鉴权和团队访问属于后续独立安全方案。
- UI 写请求使用每次启动生成的随机 nonce 和自定义请求头；MCP 本地客户端不依赖浏览器 Origin，但仍必须通过设备范围、只读门禁、参数校验和审计。
- 敏感节点文本、密码、nonce、凭据和完整用户输入不得写入普通日志或诊断复制内容。

### 5. Web 正式工程

- 正式 UI 使用 React 19 和 Vite 6，与原型保持同代。
- 样式采用语义 CSS 变量以及原生 CSS 或 CSS Modules，不引入 Tailwind。
- 正式图标统一为 Phosphor，不与 Hugeicons 混用。
- URL 是页面、设备、工作台 Tab 和设置分组的可恢复状态源。路由至少包含设备列表、群控、设备工作台五个 Tab 和设置分组。
- 浏览器返回与 `Cmd+[` 共用 History；刷新必须恢复当前页面、设备标识和 Tab。
- 快照实体、视频帧、敏感会话信息和 nonce 不进入 URL。
- HTTP 服务状态使用契约客户端和请求缓存层；局部 UI 状态优先使用 React reducer 与 context。没有状态模型和测量证据前不引入额外全局状态机库。
- 工作台切换 Tab 只替换右侧任务内容，不重新挂载设备画面、不重连媒体流、不销毁当前快照或选中节点。
- 切换设备保留 Tab，但必须清理旧设备快照、查询、选中节点、缓存和 WebSocket。

### 6. Core 公开契约

- 信息接口必须返回产品版本、API 版本、快照 schema 版本、进程标识、端口、nonce 和能力集合。
- 设备契约必须覆盖列表、状态、健康诊断、当前应用和受控命令，并统一使用 `deviceId`。
- `LayoutSnapshot` 至少包含 schema 版本、设备标识、平台、方向、窗口尺寸、抓取时间、截图引用、节点树和抓取来源。
- `Node` 至少包含稳定树路径键、跨平台节点名称、归一化 bounds、像素 rect、平台原始属性和子节点。
- 快照抓取必须支持幂等键、超时、部分成功、同步状态和统一错误。
- 摘要与诊断必须声明确定性、裁剪或 `partial` 状态、量化证据和统一错误。
- 媒体 WebSocket 契约必须冻结握手、编解码参数、二进制帧封装、控制消息、心跳、背压、重连和释放语义。
- 插件契约必须冻结清单、展示模式、sandbox、`postMessage` schema、授权、版本兼容和错误隔离。
- MCP 契约必须冻结工具名、输入 schema、返回 schema、读写分类和结构化错误。
- 统一错误形态至少包含成功标志、错误码、面向人的短消息和面向调用方的可执行 `hint`，不得向 UI 或 Agent 暴露裸堆栈。
- 过期快照绑定的合法 `ref` 返回 `SNAPSHOT_STALE`；从未存在、格式非法或无法解析的 `ref` 返回 `REF_NOT_FOUND`。
- 设备离线返回 `DEVICE_DISCONNECTED`；只读拦截返回 `READ_ONLY_MODE`；写队列等待超过 5 秒返回 `DEVICE_BUSY`；非法参数返回 `INVALID_ARGUMENT`。
- 前端与 Core 产品版本不一致时阻断进入。API 与快照 schema 版本按显式兼容矩阵判断，不提供关闭校验的生产开关。

### 7. MCP 工具集

- V0.1 期望提供 9 个原子工具：窗口尺寸、设备信息、截图、布局 XML、tap、swipe、文本输入、按键和 XPath 查找。
- V0.1 期望提供 3 个高阶工具：语义摘要、布局诊断和元素查找。
- UI 不硬编码工具名称、数量和读写类型，实际展示必须来自运行时 `tools/list`；契约测试对 V0.1 期望的 12 个工具进行门禁。
- `.lsnap` 存档、快照 diff 和内置 MCP Inspector 对应的工具与入口不进入 V0.1。
- V0.1 不提供任意 shell 或 exec MCP 工具。
- 设备断开时端点保留结构化不可用状态；设备重新连接后自动恢复可用。

### 8. 页面、导航与状态

- 设备页是默认入口；未实现的主页、应用和命令导航项在生产包隐藏。
- V0.1 工作台 Tab 顺序固定为：常用、插件、元素查看、MCP、布局智能。
- 布局智能在 V0.1 只包含语义摘要和六类异常诊断；存档与 diff 不展示。
- 群控在 V0.1 只提供多路画面预览和进入单设备工作台，不提供同步写操作广播。
- 独立日志浏览页不进入 V0.1。错误、插件和 MCP 场景通过内联错误、脱敏诊断和固定日志目录完成恢复。
- 设置页包含外观、设备与驱动、投屏、安全和关于；存档目录、远程监听和自动更新等后续设置不进入 V0.1 生产界面。
- 所有异步区域必须覆盖加载、成功、空、错误和重试状态。
- 状态文案必须说明发生了什么、哪些内容仍可用以及下一步可执行操作。
- 设备离线、抓取失败、媒体重连和 Core 恢复不得无条件清空仍可查看的最后一帧或快照。

### 9. 视觉与布局基线

- 视觉方向是 Apple 品质感、工具克制和高信息密度；使用一个品牌蓝、冷中性灰、4px 栅格、系统字体、克制阴影和语义 Token。
- 正式迁移使用可运行原型的几何基线：标题栏 56px、管理侧栏 188px、工作台控制轨 68px。设计系统中的另一套几何常量不与其混用，后续应回写统一。
- 应用基准窗口为 1480×1060，默认窗口为 1440×900，最小窗口为 1280×800。
- `BrowserWindow` 使用 `hiddenInset` 标题栏，交通灯由 macOS 绘制；浏览器原型中的模拟交通灯不迁移。
- V0.1 不引入自定义 `NSVisualEffectView` 原生模块；标题栏和侧栏使用 CSS 材质与不透明回退。
- 外层设备面板按原型限制在 330–720px；内层属性面板最大宽度由检查器容器实时计算并夹紧。
- 分隔条必须提供鼠标拖拽、方向键 12px 步进、Shift 32px 加速、Home/End 边界跳转和双击复位。
- 分隔条拖拽期间使用窗口捕获阶段的指针移动、抬起和取消监听，完成后必须清理监听与全局拖拽状态。
- 桌面壳不采用原型的移动卡片响应式信息架构；窗口不足最小尺寸时由壳限制，而不是重排核心工作台。
- 普通 `true` 与 `false` 使用中性文本或图标，红色只用于真实错误或诊断风险。
- 未实现入口默认隐藏，不展示无响应的死入口或误导性的未来能力卡片。

### 10. 动效与性能

- 基础动效 Token 为 100、180、260 毫秒，默认曲线为快速进入、柔和结束的非弹跳曲线。
- 页面切换使用克制的交叉淡化与最多 8px 位移；Tab 只替换右侧任务面板并使用 180 毫秒级反馈。
- 侧栏宽度不做持续动画；旧内容淡出后一次提交几何变化，只对子元素执行 opacity 或 transform 反馈。
- 日常按钮不使用 overshoot；按压反馈不得缩窄焦点环或代替 loading、成功、失败、只读和禁用状态。
- 启用减弱动态效果时关闭位移、缩放和淡入淡出，只保留即时颜色与可见状态变化。
- 按压到首个视觉帧不超过 50 毫秒；页面切换在 180–260 毫秒内完成；Tab 切换为 180 毫秒上下 20%。
- Intel 验收机在 1280×800 下连续切换 30 次，帧时间 P95 不超过 18.2 毫秒。
- 动效开启与关闭分别运行 60 秒，展示丢帧率差不超过 2 个百分点；切换期间不得出现超过 50 毫秒的主线程长任务。
- 未达标时依次取消页面位移、取消双层退出动画，最后只保留即时颜色反馈，不得通过降低投屏画质掩盖 UI 动效问题。

### 11. 媒体与资源管理

- 目标媒体实现使用 DedicatedWorker 与 `VideoDecoder`；是否使用 `OffscreenCanvas` 由技术验证决定。
- 解码队列最多保留 2 帧，积压时丢弃旧帧；每个 `VideoFrame` 在绘制或丢弃后立即释放。
- 页面隐藏、设备离线、切换设备和退出工作台时必须暂停解码并释放 decoder、socket 和画布资源。
- WebCodecs 不可用、配置失败或连续解码错误时降级为截图轮询，并在 UI 显示明确的降级状态。
- 视频断流按 1、2、4 秒重连三次；失败后保持最后一帧并提供稳定错误状态。
- 投屏与 UI 动效分别采集解码 FPS、展示 FPS、丢帧率和主线程长任务，不能以线程设计推断性能达标。

### 12. 插件边界

- V0.1 只扫描固定插件目录、读取合法清单、加载 iframe、重新加载单个插件和打开固定目录。
- 插件安装、卸载、启用和禁用管理不进入 V0.1。
- 插件 iframe 必须启用 sandbox，不直接获得宿主同源权限；设备能力通过宿主 `postMessage` 桥接。
- 插件写请求统一经过只读门禁、参数校验、授权和 ActionLog。
- `$u.shell` 默认关闭；用户可选择本次允许、始终允许该插件或拒绝。破坏性命令只允许单次确认。
- 生产包拒绝任意远程插件 origin；指向本地开发服务的插件只允许在显式开发构建中使用。

### 13. 打包与发行

- Core 发行环境固定为 Python 3.10 与锁定依赖，不依赖系统 Python。
- V0.1 分别产出 `arm64` 和 `x64` 两套制品，不承诺 universal。
- 每套 Electron、Core、ADB、scrcpy 及嵌套二进制必须保持相同架构。
- 构建顺序固定为 Web 构建、写入 Core 静态资源、构建 Core、校验制品哈希与版本、组装 Electron、递归签名嵌套二进制、签名应用、生成 dmg、公证、staple、干净机验证。
- V0.1 不打入自动更新运行依赖，只保留后续扩展接口。
- PyInstaller 单文件是目标方案，但必须先验证启动时延、嵌套签名和公证；如需改为 onedir 或 Nuitka，必须回写并重新评审，不能在实现阶段静默切换。
- Electron、打包器和全部依赖必须使用固定版本并进入锁文件，不使用“当前稳定版”作为可复现描述。
- 最低 macOS 版本、包体和安装后体积必须在首个可运行发行样本上建立基线，再由产品冻结阈值，本规格不虚构数值承诺。

### 14. 实施顺序与准入条件

1. M0 契约冻结：关闭文档冲突，明确第一方 Core 工程坐标和负责人，冻结 API、WebSocket、MCP、插件、错误码和兼容矩阵，并使契约测试可运行。
2. M0.5 高风险验证：验证双架构最小 Core 制品、PyInstaller、签名公证、Electron sandbox、精确 origin、CSP、媒体 Worker 和插件 sandbox。
3. M1 壳启动闭环：完成窗口、启动与错误页、单实例、Core 状态机、日志、版本握手和进程回收，缺失、超时、崩溃、端口冲突测试必须通过。
4. M2 正式 Web 骨架：迁移 Token、构图、分隔条与基础组件，建立 URL 路由、主题、全局错误、设置和五 Tab 骨架，视觉回归与键盘检查必须通过。
5. M3 真实主链路：接入真实 Android 设备列表、投屏、截图降级、快照、元素树、XPath 和只读门禁，真机主链路与降级路径必须通过。
6. M4 V0.1 完整能力：完成五 Tab、摘要、诊断、MCP、插件、群控预览和 ActionLog，PRD V0.1 不得缺项，后续入口不得泄漏。

9. M7 发布评审：提交 PRD 验收报告、真机结果、安全与无障碍结果以及风险关闭记录，所有阻断项关闭后才能发布。

### 15. 产品量化验收

- 正常环境下 Core 就绪 P90 不超过 10 秒，15 秒硬超时。
- 已授权 Android 设备接入后 3 秒内出现在设备列表。
- 冷进入工作台首帧不超过 3 秒；已建立媒体链路的暖切换首帧不超过 500 毫秒；持续投屏帧率至少 15fps。
- 1000 节点级“冻结 → dump → 截图”端到端 P90 不超过 2 秒。
- 画面选中到树定位不超过 200 毫秒；画面高亮与 bounds 误差不超过 2px。
- 横屏、竖屏点击注入坐标误差均不超过 2px；旋转后必须重新取得 `windowSize`。
- XPath 在 1000 节点树上的查询不超过 300 毫秒。
- `get_layout_summary → find_element → tap` 在真实设备连续 100 次成功率不低于 98%。
- 摘要单轮不超过 1200 token，可交互元素无遗漏；同一快照重复生成结果完全一致。
- 50 例指定元素定位正确率不低于 95%。
- 六类布局异常样本的整体检出率不低于 90%，3000 节点内诊断耗时不超过 300 毫秒。
- 设备离线后 5 秒内更新状态，禁用写操作并保留最后画面和快照。
- Core 被强杀后按预算自动恢复；应用退出后无孤儿 Core 或投屏进程。
- 连续 dump 100 次内存增长不超过 10MB。
- 默认无外发网络请求、无 License 弹窗、无注册窗、无联网校验。

## 测试决策

### 1. 测试原则

- 测试只断言用户可见行为、可访问性树、公开协议、日志和操作系统进程状态，不断言 React 私有 state、reducer action、CSS 私有类名或内部函数调用顺序。
- 优先使用最高层、最少数量的接缝覆盖完整行为，避免壳、preload、renderer 和 Core 各自维护不一致的私有 mock。
- 所有异步与失败测试必须使用确定性事件驱动，不依赖不可控固定等待。
- 每个发布门槛必须有可复现命令、输入样例、编程式断言和留档结果；“看起来完成”不能替代验证。
- 视觉观感、macOS 原生手感和真实硬件体验由人最终签收，但其前置构建、状态、键盘、ARIA、时长、帧时间和资源释放必须自动化。

### 2. 唯一主要自动化接缝

主要接缝定义为“真实 Electron 应用 + 可控假 Core 子进程 + 正式 Web 构建产物”。

该测试台必须：

- 启动真实 Electron 主进程、preload、壳内启动与错误页以及正式 React Web UI，不直接挂载页面组件。
- 以真实子进程和真实随机端口运行假 Core，使壳的 spawn、READY、信息校验、导航、健康检查、重启和退出回收路径保持真实。
- 使用与正式 Core 相同的版本化 HTTP、WebSocket、MCP 和插件 schema。
- 能脚本化注入就绪、超时、崩溃、版本不兼容、nonce 不匹配、端口冲突、设备在线、未授权、掉线、恢复、快照超时、空层级、部分同步、媒体断流、背压、只读拒绝和结构化错误。
- 通过角色、可访问名称、键盘、鼠标和公开 URL 操作 UI。
- 从假 Core 收到的公开请求、WebSocket 连接数、MCP 返回、ActionLog 和进程存活状态判断后端结果。

### 3. 契约一致性门禁

- 同一组 OpenAPI、JSON Schema、媒体帧样例、插件消息样例和 MCP 快照同时约束假 Core 与真实 Core，避免测试替身与生产契约漂移。
- 信息接口、设备、快照、摘要、诊断、写操作、媒体、插件和 MCP 的成功与错误样例均必须通过 schema 校验。
- 产品版本不一致必须阻断；API 与快照 schema 按显式兼容矩阵通过或拒绝。
- MCP `tools/list` 快照必须包含 V0.1 的 9 个原子工具和 3 个高阶工具，不包含 V0.2 工具。
- UI 展示端口必须与真实监听端口一致，端口变化后旧配置失效提示必须可见。

### 4. 壳与进程测试

- 验证启动页先于 Core 就绪出现，READY 与信息接口校验后才进入设备页。
- 验证制品缺失、15 秒超时、nonce 不匹配和版本不一致时错误页仍可用。
- 验证错误页的重试、复制脱敏诊断信息和打开固定日志目录。
- 验证端口冲突后新端口同步到 Web UI 和 MCP 配置。
- 验证健康检查、1/2/4 秒退避、三次预算、稳定 60 秒重置和预算耗尽错误态。
- 验证单实例只唤醒现有窗口。
- 验证退出后 Core、投屏子孙进程全部消失且端口释放。
- 验证任意 IPC channel、路径、URL、导航、弹窗和权限请求被拒绝。

### 5. Web UI 外部行为测试

- 验证 URL 刷新恢复、History 返回与 `Cmd+[` 一致。
- 验证设备列表的加载、空、连接、未授权、离线、工具链缺失和枚举超时状态。
- 验证切 Tab 保留快照与选中节点，切设备保留 Tab 但清理旧设备上下文和 WebSocket。
- 验证五个 Tab 只替换右侧任务内容，设备画面不重新连接。
- 验证非法 XPath 不发请求、零命中不清空选中、无快照提供抓取入口。
- 验证抓取期间重复触发不产生第二个请求。
- 验证画面、层级树和属性面板三方联动及定位时限。
- 验证只读模式同时禁用 UI 写入口、阻止画面写请求、使 MCP 返回 `READ_ONLY_MODE` 并记录拦截审计。
- 验证插件错误隔离、平台不匹配、shell 授权和破坏性命令单次确认。
- 验证所有错误都包含问题说明、仍可用内容和可执行下一步。

### 6. 媒体、性能与资源测试

- 验证正常 WebSocket 首帧、心跳、背压和资源释放。
- 验证 WebCodecs 不可用或解码失败后自动进入截图模式并显示降级标识。
- 验证页面隐藏、设备离线、切设备和退出工作台后旧 WebSocket 关闭且不再消费帧。
- 验证断流按 1/2/4 秒重连，三次失败后进入稳定错误态。
- 验证队列不超过 2 帧，丢弃或绘制后释放 `VideoFrame`。
- 验证动效开启与关闭的帧时间、展示丢帧率和主线程长任务符合量化阈值。
- 验证连续抓取、切 Tab 和切设备后连接、decoder、帧对象和内存不持续增长。

### 7. 可访问性与视觉回归

- 自动验证 Tab、Tree、Separator、Dialog、Toast 和状态横幅的角色、名称、状态与焦点关系。
- 自动验证分隔条鼠标拖拽、方向键、Shift 加速、Home/End、双击复位和 `aria-valuenow` 更新。
- 自动验证 Enter、Space 与鼠标得到等价状态反馈。
- 自动验证减弱动态效果下无位移、缩放和淡入淡出，同时焦点、功能和状态宣告正常。
- 在 1480×1060 与 1280×800、浅色与深色主题下，为设备页、群控页和五个工作台 Tab 建立视觉回归基线。
- 人工走查真实 macOS 交通灯、拖动区、窗口缩放、菜单、Finder 打开目录、系统主题、降低透明度和整体原生手感。

### 8. 真实 Android 发布门禁

- 在至少 3 台不同厂商 Android 真机上验证授权、枚举、投屏、控制、旋转、中文输入、拔插恢复和只读模式。
- 完整执行“设备 → 工作台 → 抓取 → 元素 → 摘要与诊断 → MCP tap”主链路。
- 验证投屏、快照、树定位、XPath、摘要、元素查找、诊断和 MCP 连续调用达到量化指标。
- 验证安全键盘、空层级、dump 冲突、设备锁屏、媒体断流和旧 `ref` 等异常路径。
- 验证默认回环访问，其他机器无法连接生产端口。
- 人工核对 20 个典型页面中的可交互元素是否完整进入摘要，并评估诊断证据是否具有业务意义。

### 9. 双架构发行门禁

- `arm64` 与 `x64` 分别在干净机完成安装、Gatekeeper、签名、公证、staple、首次启动和离线启动验证。
- 验证应用、Electron、Core、ADB、scrcpy 与嵌套二进制架构一致。
- 验证日志目录、插件目录、主题、菜单和错误页在安装包环境下可用。
- 对每个架构反复启停应用 10 次，确认无孤儿进程、无残留端口和无持续增长的临时文件。
- 验证生产包无外发网络请求、无 License、无注册和无线上 UI 依赖。

### 10. 可复用测试先例

- 现有原型的 Sites 测试通过公开 `fetch` 行为验证静态资源、路由回退和构建产物，可复用“测公开行为、不测内部实现”的原则。
- 现有原型已经为图标按钮、Tab、Toast 和双层分隔条提供稳定的可访问语义，可作为正式测试选择器与交互要求的基线。
- 现有原型的构建与 Sites 测试只能作为构建先例，不能证明 URL、真实设备、Electron、契约、安全、媒体或发行行为完成。
- 上游 Core 的设备驱动与 API 测试只能复用测试思路和回归样例；第一方 Core 必须通过本规格冻结的契约门禁。

### 已裁决的文档冲突

- “启动 10 秒”与“启动 15 秒”统一为：P90 不超过 10 秒，15 秒硬超时。
- “四个工作台 Tab”统一为五个，布局智能必须进入 V0.1。
- MCP UI 使用运行时 `tools/list`，V0.1 契约期望为 12 个工具。
- `.lsnap` 导入、导出和 diff 统一移出 V0.1。
- 普通布尔值统一使用中性表达，红色只表示真实错误或诊断风险。
- 独立日志页统一移出本 Story，保留日志落盘和固定目录入口。
- 群控统一为只预览，不广播写操作。
- 未来导航与后续能力统一隐藏，不保留死入口。
- 几何尺寸统一以可运行原型为迁移基线，不兼容设计系统中的另一套常量。
- 端口统一由 Core 原子绑定，使用 READY nonce 与信息接口校验；不采用壳先探测或查询参数注入方案。
- 插件浏览统一为在 Finder 打开固定目录，不在 V0.1 内置插件商店或文件浏览器。
- 过期快照 `ref` 与非法 `ref` 使用不同错误码，避免调用方误判恢复动作。

### 与规格的偏差（待产品补确认）

1. **Core 就绪超时**：规格为「P90 ≤ 10 秒，15 秒硬超时」。实测 macOS 对 PyInstaller 产物新 inode 首次执行的安全评估为 8–20 秒（页缓存/路径/ad-hoc 签名均不可消除，最小 hello-world 包同样受影响），已调整为 **25 秒超时 + `CORE_READY_TIMEOUT` 自动重试一次**；热启动实测 0.27 秒。建议规格改判为「热启动 P90 ≤ 10 秒，首次安装一次性 ≤ 25 秒」，彻底消除需 Developer ID 签名（M6）。
2. **打包方案**：PyInstaller 单文件改为 **onedir**（每次启动 7-8 秒自解压不可接受），制品布局为 `Resources/core/layoutsee-core` + `Resources/core/_internal/`，已在 technical-design.md §23.2 关闭决策门。
3. **媒体链路**：V0.1 当前交付为**截图轮询模式**（可配置 400–5000ms），scrcpy 实时视频与 WebCodecs 解码未实现；UI 以「截图模式」标识，不伪装实时。暖切换 500ms 首帧、15fps 等媒体量化指标随实时链路 Story 一并验收。
4. **插件运行时**：仅实现固定目录扫描、清单校验、平台过滤与 Finder 打开；沙箱 iframe、MessageChannel 桥、`$u` 能力、授权 UI 未实现，UI 已明示「沙箱运行时将在后续 Story 提供」。
5. **群控**：按规格实现为只读预览（单格冻结、超阈值降频、双击进工作台），底层为截图轮询而非视频流。
6. **自动化接缝**：规格要求「真实 Electron + 可控假 Core + 正式 Web 构建」为唯一主要接缝；当前仅有单元/契约层自动化（Core 27 项、壳 8 项、契约 5 项）+ 打包二进制 curl 全链验证，Playwright 端到端接缝未建，人工测试先行。

### 手动测试反馈修复记录（四轮，全部已关闭）

1. 打包入口引用已迁移的 `server.main()` 导致 Core 启动即 ImportError。
2. 三处非重入锁嵌套死锁（设备注册表/快照 ref/设置存储），设备页、设置保存、ref 解析会挂死；已重构并补死锁回归测试。
3. 首启动 19.9 秒超 15 秒预算：定位为系统对新 inode 的评估成本，切 onedir + 25s 超时 + 自动重试。
4. Finder 启动无终端 PATH 导致「未找到 ADB 工具链」：Core 增加候选路径探测（MacPorts/Homebrew/Android SDK）并自动持久化到设置，壳侧补充工具目录 PATH。
